# 用用户自己的知识库

知识库在手机上，源文件放在 `下载/DSH-Go/知识库/`，App 把每个文档抽成正文、切成
约 800 字的块（块之间有重叠），只在本机检索。索引不联网、不上传。

| 工具 | 用途 |
|---|---|
| `kb_search` | 按关键词检索，返回命中的片段、来源路径和块号 |
| `kb_read` | 读某一块的完整正文（用 search 给的 doc + chunk） |
| `kb_import` | 把手机上的文件复制进知识库并建索引 |
| `kb_stats` | 现在有多少文档、多少块、占多少空间 |
| `web_crawl` | 把网页正文抓进知识库（可顺着链接抓几页） |

## 什么时候用

- 用户问「我的资料里」「之前存的笔记」「那个合同/说明书怎么写」——**先 `kb_search`**，
  不要凭记忆回答。
- 需要精确引用（条款、数字、原话）时，`kb_search` 拿到块号再 `kb_read` 读整块，
  必要时读相邻块（chunk ± 1）。
- 用户让你把某个文件存进知识库时才 `kb_import`；导入会复制文件，**先问一句**。

## 怎么引用

- 回答里给出处：文档路径 + 大意，例如「据 `笔记/报销规则.md`」。
- 只引用搜到的原文，不要补充没出现的细节。
- 搜不到就直说「知识库里没有这个」，不要编，也不要当成搜索过网络。

## 网页资料

- 用户给一篇长文/一个系列页，说「存下来以后查」——用 `web_crawl`。
- 默认只抓这一页和它的直接链接（`depth` 1）、最多 10 页、只在本站内；用户要更多再调大。
- 需要登录态或页面靠 JS 出内容的，把 `render` 设为 true：会用内置浏览器逐页打开，慢但准。
- 抓完就是知识库里的普通文档（`网页/<站点>/…….md`），之后照常用 `kb_search` 检索，
  回答时给出这个路径。
- 再抓同一个站是增量的：内容没变的页不会重写。
- **不要用它镜像整站**；用户要「整站」时先问清楚是哪几页。

## 边界

- 支持 txt / md / html / csv / json / docx；**PDF、Excel、图片暂不支持**，遇到就直说
  并建议用户转成 txt/md 或截图后由用户自己看。
- 知识库里是用户的私人资料，除用户要求的回答外不要复述无关内容，也不要发到外部。
- 文档多、结果杂时把 `limit` 调小（默认 8），用更具体的词再搜一次。
- 用户想在界面上看/删/重建，告诉他：设置 → 帮助与关于 → 能力控制 → 知识库。
