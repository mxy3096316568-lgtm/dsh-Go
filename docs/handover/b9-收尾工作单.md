## 线二：插件 API 扩面（一次全做）

目标：插件从“能画界面”变成“能动数据和动作”，但**授权按插件、可撤销、危险三类每次确认**。

### 能力清单（一次全加）

| 能力 | 给什么 | 风险 |
|---|---|---|
| `sessionText` | 当前会话全文（含历史轮次，只读） | 中：数据外流 |
| `selection` | 用户选中的文字 | 低 |
| `files` | 插件沙箱目录读写（`$DSH_HOME/dsh-go/plugins/<name>/data/`，禁 `..`） | 中 |
| `send` | 把文字填进发送框（**不自动发送**）；发消息必须经用户点一次 | 高 |
| `notify` | 发一条本机通知（复用 `dsh/notify`） | 低 |
| `phone` | 调手机操控（读屏/点按），**默认关** | 高 |
| `tools` | 让插件触发指定工具，**默认关** | 高 |
| `schedule` | 让插件登记定时任务，**默认关** | 中 |

### 协议改动

1. `runtime/bridge/dsh-go-bridge/lib/native/capabilities.js`：`FEATURES` 加这 8 个；校验允许值、未知值 warn 忽略（保持旧插件逐字节不变）
2. 协商：`contributions?features=…` 与 `hello/welcome` 的 `features` 一起扩；App 只在有插件声明时才带
3. `lib/native/capability-runtime.js`：新增宿主服务处理（请求 → App → 应答），每类有超时与大小上限
4. 桥接提供 `ctx.dshGo.on/panel/strip` 现有调用不变；新能力走 `ctx.dshGo.capability(name, handler)`

### App 端

1. `app/lib/plugins/native/native_capabilities.dart`：能力注册与协商列表
2. `app/lib/state/consent_store.dart`：授权键加插件维度——`plugin:<package>:<capability>`（现在只按工具名，**必须修**，否则插件冒名继承授权）
3. `native_taps.dart`：`wants` 走同一套授权；关掉 `能力控制 → 插件权限` 时全部失效
4. `capabilities_page.dart` + `consent_page.dart`：授权记录显示「插件 / 能力 / 时间 / 依赖」，可逐条撤销与全部清除
5. 危险三类（花钱 / 删除 / 对外发送）**永不给永久**，`send` 只能填框，`phone` 每次确认

### 测试（必须有）

- `runtime/tests/native-capabilities.mjs`：声明→协商→调用→超时→未声明被拒
- `app/test/plugins/native/native_capabilities_test.dart`：授权、撤销、能力开关联动、冒名防护
- 文档：`docs/design/native-plugins-protocol.md` §11 扩到 v1.3，写清每类权限与拒绝码

1. `flutter analyze` = **No issues found**

6. 出包后：校验包内容 → 打标签 `apk-b9-plus` → 更新 `docs/handover/`（行动库、交接、测试清单）
