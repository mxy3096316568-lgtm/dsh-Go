## 复核结果（按代码对过）

| 编号 | 现状 | 根因（已定位） | 改法 |
|---|---|---|---|
| P1-1 上传误报失败 | 真 bug | `upload()` 校验 `input.files` 太早；页面在 `change` 里异步填充/或换帧 | 改成轮询 200ms×10 等本次 ref 的 `files.length===1`，超时才报失败 |
| P1-2 代理 duplicate key | 真 bug | 只对「URL 订阅」走清洗；直接粘贴 YAML 的路径用了原文，`mode`/`log-level` 没去掉 | 两条路径都过同一个 sanitize：按行解析顶层键，已存在就覆盖，不追加第二份 |
| P1-3 端口占用误报 | 真 bug | Kotlin 端有 `port_in_use`，但启动后健康检查超时分支把它盖成「订阅可能有问题」 | 启动前先 bind 探测；超时分支先探端口：被占 → `port_in_use`（提示换端口），未占 → 内核问题 |
| P2-4 开关无反馈 | 真 bug（部分修了） | `proxy_page` 有「启动中…」，但开关的 `onChanged` 在未配置/异常时提前 return | 点击立刻置「启动中…」并禁用；失败保留「失败」状态，不回滚成「已停止」 |
| P2-5 PDF 静默收下 | 真 bug | `kb_import` 先复制再建索引，不支持的类型复制完才发现 | 先按扩展名判断：不支持直接 `{ok:false,error:"unsupported_type"}`，**不落盘** |
| P2-6 切标签清空 | 真 bug（偶发） | 切到 `file://`/错误页时重建 WebView 抛错，被当成“标签全没了” | 重建失败保留原标签并返回明确错误；切换前判存活 |
| P3-7 finalUrl 串台 | 真 bug | 复用了上一个 WebView 的 `url` | 取当前标签 `webView.url`，等 `onPageFinished` 后再读 |
| P3-8 空结果文案矛盾 | 真 bug | `kb_search` 固定用 `EMPTY` 提示 | 有文档无命中时说「没有找到包含该词的文档（当前 N 文档 M 块）」 |

- P1-3：端口被占时报「端口 7890 已被其他应用占用，请换端口」；换端口能起；停止后端口释放
- P2-4：点击 1 秒内出现「启动中」，5 秒内明确成功/失败，失败不回滚
- P2-5：导入 PDF 返回失败并说明，知识库目录不新增文件
- P2-6：切到 file://、错误页后标签列表不变
- P3-7：`open` 的 `finalUrl` 与 `location.href` 一致
- P3-8：空命中文案不再自相矛盾
